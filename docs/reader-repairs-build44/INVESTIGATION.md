# Build 43 真机问题与下一版修复验证

用户已安装 Build 43，并报告连续滚动突然回到第一章、倒退或跨到不相邻章节。本次不以帧率改善代替阅读顺序验收；当前文档记录源码调查和诊断，最终结果另由成功运行与真实 IPA 校验补充。

## 连续滚动

Build 43 的 `synchronizeScrollRows` 直接排序所有已完成预加载的章节。后台完成顺序可能是 n、n+2、n+1：缺少 n+1 时仍将 n+2 紧跟 n，章节在表格中并不连续。随后补回缺章又改变已有行的位置。

另一个风险是 `performBatchUpdates` 没有等待 completion 就释放 `rebuilding`。相邻异步结果可以在 UIKit 的上一轮几何更新尚未结束时发起下一轮插删。旧代码也会在 tracking/dragging/decelerating 时裁剪前方行并修改 contentOffset，锚点只从首个可见 row 取值；若该行被修剪，补偿直接失效。不能由这些源码风险断言真机每次乱跳都来自唯一原因。

第一轮新增的真实 UIKit 回归（run 43437390546，源码 db77ccf）实际捕捉到：即使使用同步 begin/endUpdates 和 layoutIfNeeded，前插/裁剪后同一屏幕位置的 row ID 发生变化，字符锚点违反计数增长。这是实际窗口/字形回归失败，保留在 Actions，不计为通过。该轮 14 通过、2 失败；另一失败是新可点击进度区域改变无障碍层级，使旧章标题查询找不到元素，正文实际跨章行为另有检查。后续采集保留子元素，未删除原章节断言。

修复采用连续章节窗口、稳定章节 UUID + UTF-16 row ID、generation 检查和串行表格事务：

- 手指拖动或惯性期间，仅向已有连续尾部追加已准备的后续章节，不前插、不删前方行、不恢复旧移动偏移。
- 等待 UIKit append completion 后再接收下一轮窗口变更；过期 generation 或旧 table 的完成回调不能更新当前阅读器。
- 停稳时使用已经准备的字形和固定高度重新挂载窗口，同一事务内恢复实际可见 row/行内位置，避免 UIKit 对前删动画的偏移补偿选择另一段文字。此处没有重新读取/分页/排版正文。
- 保留实际可见章节和相邻缓存，惯性结束后回收临时窗口；缺失目标锚点时报可恢复错误，保留原进度，不退回章节 0。
- 显式导航、字号/视口重排和阅读器退出取消旧任务；设置浮层打开时保持实际阅读器可更新。排版变更去抖 140ms，并检查任务取消。

DEBUG 诊断只记录章节/字符位置、实际 TextKit 命中、row ID、contentOffset/contentSize、窗口插删、generation 和违反计数，不打印真实小说正文。高压 UI 回归还检查屏幕可见 canvas 的实际文字和 frame，使用原创样本章节标记，与逻辑锚点和纸面位移交叉核对；不只验证 progression 增长。

## 书签、设置与数据兼容

Build 43 的 `bookmarkAdded` 是按钮本地的一次性状态，`ReaderSession.bookmark()` 和 `LibraryStore.addBookmark()` 无条件追加。改为按稳定位置查询和添加/删除；时间戳和派生进度不作为 TXT 书签身份。章节或字符位置不同的书签保留，当前可见页/行包含已有书签时显示已收藏。旧索引仅去除相同 book/章节/UTF-16 或相同 EPUB locator 锚点的完全重复项，保留第一条 ID。

`ReaderSettings.showBottomProgress` 缺省为 true，旧枚举值和既有设置字段保持兼容。读取旧索引或发现重复书签时，在第一次写入前将原始字节备份为 `library-before-build44.json`；备份失败则不写新索引。正文、书籍/章节 ID、数据目录和导入事务保持原有约定。

设置变更立即更新真实正文和当前浮层主题；排版任务去抖并取消过期结果，设置落盘另去抖 250ms，关闭/退后台可靠提交。进度关闭时移除整个 28pt 视图，不保留占位。假示例预览卡已删除。

纯成功导入使用一个约 1.8 秒、可替换且不拦截操作的中间轻提示；重复、部分失败和失败保留实际原因、复制诊断与历史结果入口。“我的”技术信息合并到“关于予盈”，许可证与素材说明仍完整保留。
